# HR 筛选标准与评分维度

## 四大评分维度

### 1. 岗位匹配度（权重 30%）

- 技术栈与 JD 要求的重合度
- 项目经验与岗位方向的相关性
- 技能清单覆盖 JD 核心关键词的比例
- 扣分项：堆砌不相关技能、项目方向与岗位偏差过大

### 2. 经历量化度（权重 30%）

- bullet 中是否包含可量化的结果（数字、比例、规模）
- 避免"优化了性能" → 改为"优化了查询性能，响应时间降低 60%"
- 避免"提高了效率" → 改为"将构建时间从 120s 降至 30s"
- 0 量化的简历直接降级处理

### 3. 逻辑清晰度（权重 20%）

- 经历按时间倒序排列
- 每条 bullet 逻辑完整（背景→行动→结果）
- 无重复表述、无矛盾时间线
- 结构清晰，模块分明

### 4. 关键词匹配度（权重 20%）

- JD 中出现的技术名词在简历中的覆盖率
- 核心关键词：框架名、语言名、工具名、协议名
- 加分项：项目描述中自然出现 JD 关键词（而非技能清单堆砌）
- 扣分项：关键词堆砌但不出现在项目描述中

## 筛选流程

1. ATS 初筛：关键词覆盖率 < 60% 直接淘汰
2. HR 人工筛选：一页纸原则 + 量化度 + 排版
3. 技术面试官：项目深度 + 技术方案合理性

## 常见淘汰原因

- 无量化数据（最常见）
- 项目描述过于笼统（"做了个系统"）
- 技能堆砌但项目无体现
- 简历超过一页
- 格式混乱、错别字
